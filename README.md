# 小说按字数切分

把一本小说切成「每天读一份」的片段，在手机或电脑上逐天读完。
支持 **TXT** 和 **EPUB**，不需要安装任何第三方库。

## 两条硬约束

1. **绝不切断句子或段落。** 每一份的最后一段都是完整结束的，不会出现半句话。
2. **每份不超过 6500 字。** 默认目标 5500 字（约纸质书 8 页），下限 4000 字。

原理：候选切点只取完整的段落末尾，再用 DP 全局选一组切点，
让每份尽量贴近目标字数、尽量落在章末、尽量停在场景分隔处。
**不调用任何模型，纯本地计算，token 消耗为 0。**

## 怎么用

### 方法一：拖进去（推荐）

把小说文件直接拖到 **`启动.cmd`** 上，等窗口跑完就行。

也可以双击 `启动.cmd`，窗口会问你把书放在哪 —— 把文件拖进窗口或粘贴路径，按回车。

结果会放在书所在的位置，文件夹名是「**书名_split**」。
第一次运行需要电脑上有 Python 3.10 或更新的版本（没有的话脚本会提示怎么装）。

### 方法二：命令行

```powershell
python novel_split.py 小说.txt
python novel_split.py 小说.epub -o 输出目录
python novel_split.py 小说.txt --target 5500 --max 6500 --min 4000
```

可以一次给多个文件，也可以不给文件（会交互式询问路径）。

### 参数

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| `--target` | 5500 | 每份目标字数 |
| `--max` | 6500 | 每份硬上限，绝不会超过 |
| `--min` | 4000 | 软下限，低于此值会罚分 |
| `-o` | `<书名>_split` | 输出目录 |
| `--no-txt` / `--no-epub` | — | 只要其中一种输出 |
| `--no-header` | — | TXT 不加开头的天数表头 |
| `--no-images` | — | EPUB 里不带原书插图 |
| `--keep-toc` | — | 保留开头的目录页（默认跳过） |
| `--force` | — | 书有问题（扫描版 / 太短）时也强行切 |

想按纸质页数换算：`--target` = 每天页数 × 每页字数。常见平装小说每页约 700 字，
所以 8 页 ≈ 5500 字，10 页 ≈ 7000 字。

## 输出

```
<书名>_split/
├── txt/第01天_第一章-第三章.txt ...
├── <书名>_split.epub
└── 清单.md
```

- **txt/**：每天一个文件，开头一行标明天数、覆盖章节、实际字数
- **epub**：一个文件，每天一章，带目录，手机上能跳转、能记进度；
  原书插图按原来的位置一并打包进去
- **清单.md**：每天的字数、估算 token、章节范围，方便对账

## 每次运行会打印

```
=== 书名 ===

载入           0.044 s
结构解析         0.006 s
DP 切分        0.011 s
写出 TXT       0.018 s
写出 EPUB      0.101 s
写出清单         0.001 s
合计           0.182 s
```

「估算 token」是给你将来万一要喂给 AI 时做参考的粗略换算，不是真实消耗 ——
这个工具本身一个 token 都不花。

## 遇到「这本书切不了」

### 扫描版（图片版）EPUB

会看到这样的提示：

```
════════════════════════════════════════════════════════
  这本书切不了：它是扫描版（图片版）EPUB
════════════════════════════════════════════════════════

  文件    《某扫描书》
  统计    文字只有 151 字，却有 40 张图片

为什么会这样
  这本书的正文不是文字，而是一页一页扫描（或拍照）出来的图片。
  本工具是按「每天读多少字」来切的，没有文字就没有东西可切。
```

**原因**：正文是图片，文字层是空的（只有封面、版权页残留几十个字）。
**办法**：先用 OCR 把图片认成文字，再拿转出来的 TXT 跑到这个工具上。

| 类型 | 推荐工具 |
| --- | --- |
| 有界面的 | Umi-OCR（免费开源，中文好）、ABBYY FineReader、Adobe Acrobat「识别文本」、微信/QQ 图片转文字 |
| 命令行的 | `ocrmypdf`（PDF）、`PaddleOCR`（图片） |

只想看图、不需要按字数切着读的话，直接看原 EPUB 就行，不用经过这个工具。

### 其他报错

程序会区分三种情况分别说明原因：扫描版 / 完全没有文字 / 内容太少（不到 2000 字）。
PDF 会被明确拒绝，并提示先转成 EPUB 或 TXT。

## 检查工具

```powershell
python 诊断.py sample\某本书.epub
```

只读，不写任何文件。先体检（编码、段落、章节、图片、段落长度分布），
再逐条验证硬约束：不超过上限、正文零丢失零重复、每份结束在完整句尾、每份从完整段落起、章末对齐率。

换一本新书时先跑一遍它，能提前看出这本书有没有结构上的坑。

## 已知限制

- **不支持 PDF / DOCX**。要从这两种格式来，先转成 TXT 或 EPUB。
- **扫描版读不出文字**（上面已说明）。
- 极少数「墙文本」（整本一段到底、没有段落换行）只能退化到按句子切。
- 单段超过 6500 字时，只能在段内按句末退让切分，这时「不切断段落」无法满足，
  程序会在报告里明确提醒。
- 章末对齐率不是 100%（真书实测 21/49）。想提高就得放宽字数浮动、牺牲每天的均匀度，
  这是取舍不是 bug。
- 控制台显示中文乱码的话，先执行 `chcp 65001` 再运行；用 `启动.cmd` 则不会遇到。
